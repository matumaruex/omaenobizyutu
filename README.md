# 余白の美術館

今の気持ちをことばにすると、柔らかな光に包まれた球状の空間に、実在する絵画が現れる。日本語の3D美術館Webアプリです。絵を生成する機能はありません。

## インストールせずにデモを試す

このチャットで配布する確認用ZIPを解凍し、`yohaku-demo.html`をPCのChromeやEdgeで開いてください。画像とプログラムを1つのHTMLに同梱しているため、APIキー・Node.js・サーバー起動は不要です。感情によるデモ選定、上下左右の見回し、作品の拡大鑑賞を試せます。AIによる選定は本体で利用します。

HTMLを再生成する場合は、依存をインストールしたリポジトリで`npm run demo:portable`を実行します。出力は`artifacts/yohaku-demo.html`です。入力はブラウザ内で処理します。元画像の権利情報は作品情報画面から参照できます。

確認用HTMLはHTTPで読み込んだ後、通信をオフにして展示作成・鑑賞をPC／スマホ相当画面で確認しました。この管理環境では`file://`への直接移動がブラウザの管理ポリシーで禁止されているため、ローカルファイルとしての直接起動試験は未実施です。

## 起動

Node.js 24 LTS と npm を使用します。繰り返し同じ環境でビルドできるよう、Node.jsは24系に固定しています。

```bash
npm ci
npm run dev
```

ブラウザで http://localhost:3000 を開きます。APIキーもデータベースも不要で、同梱作品を使う無料デモが動きます。

管理環境でホームのnpmキャッシュに書き込めない場合は、`npm ci --cache /tmp/yohaku-npm-cache` を使ってください。

本番用：

```bash
npm run build
npm start
```

Vercelのテスト用サイトへ配信済みです。スマホでは[美術館の確認用URL](https://bijutsukan-git-codex-museum-preview-matumaruexs-projects.vercel.app)を開いてください。Vercelのログイン画面が出る場合は、接続したVercelアカウントで一度ログインします。

今後は`codex/museum-preview`ブランチへのpushで、このブランチの確認用URLが更新されます。利用者がZIPやコマンドを操作する必要はありません。詳しくは[確認用サイトの運用](docs/PREVIEW.md)を参照してください。

## 実装した体験

- 床・壁・天井のない球状の空間。薄紫・乳白色・淡い緑の光と霧に包まれ、絵が周囲・頭上・足元の方向に浮かびます。画像は球の中心を向き、縦横比を保ちます。
- 「空間に入る」から開始。見回す操作に絞り、「気持ちを教える」と小さな「空間から出る」だけを表示。入力欄はボタンで開きます。ヘルプ・設定は入口に、作品一覧は入力欄にまとめています。退出後は空の空間から始まります。
- 日本語自由入力、実際の処理段階に応じた待機表示、処理のキャンセル。
- 感情に応じた可変展示。無料デモは4〜8点、AIは4〜12点。配置自体は全4〜12点に対応します。
- 最大3枚ずつ画像を読み込み、デコード完了後に作品を順番にフェードインします。
- 再入力時は前の作品だけをフェードアウトし、見ている向きを保ったまま新しい展示に切り替えます。
- PC：ドラッグまたは矢印キーで見回し、作品クリックで鑑賞。スマホ：スワイプで見回し、作品タップで鑑賞。ドラッグ／スワイプの上下左右は反転しています。
- 視点は球の中心に固定。歩行・移動スティック・マウス固定はありません。ほぼ真上・真下まで見られ、入力・鑑賞中は視点操作を停止します。
- 鑑賞画面ではまず画像だけを大きく表示。作品情報と選定理由は独立して開閉できます。
- 作品一覧からの鑑賞、表示負荷の低減、OSの「動きを減らす」設定の反映。
- WebGL非対応時にも、入力・作品一覧・拡大鑑賞を使えます。
- 通信失敗・画像不足・AI失敗を画面に表示。成功前の展示は維持します。

## 技術と構成

Next.js 16 App Router / React 19 / TypeScript / Three.js / React Three Fiber / AI SDK 7 / Zod / CSS / Vitest / Playwright。

```text
src/app/                    ページ、レイアウト、スタイル
src/app/api/config/         AI設定の有無だけを返す
src/app/api/exhibition/     入力検証、無料／AI選定、失敗応答
src/components/Room.tsx     球状の背景、浮遊作品、画像テクスチャ、見回し操作
src/components/Museum.tsx   入力から展示への状態遷移
src/components/ArtworkView.tsx  鑑賞・作品情報・選定理由
src/lib/curation.ts         無料デモ、候補検索、ID検証
src/lib/ai/select.ts        サーバー限定のAI呼び出し
src/lib/layout.ts          縦横比、球面上の配置、内向きの姿勢
src/data/collection.json    作品事実と編集上の解釈
src/data/provenance.json    画像ごとの取得経路、権利、ハッシュ
public/artworks/            同梱する16点の実画像
scripts/collect.ts         公式APIからの収集（明示実行のみ）
tests/                     選定・配置・AI契約・画面操作テスト
```

判断：小規模コレクションはJSONに保存し、DB・会員登録・履歴機能を導入していません。3Dはブラウザに遅延ロードし、AIのSDKとキーはサーバーのAPIルートでのみ使用します。Drei・Tailwindは将来の必須依存とせず、今回必要な範囲をThree.jsとCSSで実装しています。

## 無料デモとAI

無料デモは日本語の語彙・明示的な否定の一部・事前編集した感情スコアを用いる決定的な選定です。文脈全体を理解するAIとは区別して表示しています。作品の関連度、作者の多様性、展示内の役割に基づき選び、文字数で展示枚数を増やしません。デモによる複雑な否定、皮肉、固有の出来事の理解には限界があります。

AIを使う場合のみ、`.env.example` を `.env.local` にコピーして次を設定し、サーバーを再起動してください。秘密鍵をGitに追加しないでください。

| 変数                       | 必要性           | 内容                                                                      |
| -------------------------- | ---------------- | ------------------------------------------------------------------------- |
| `OPENAI_API_KEY`           | AIモードのみ     | ご自身のOpenAI APIキー。`NEXT_PUBLIC_`を付けません                        |
| `OPENAI_MODEL`             | AIモードのみ     | ご自身のアカウントで利用でき、Responses APIと構造化出力に対応するモデルID |
| `PLAYWRIGHT_CHROMIUM_PATH` | テスト時のみ任意 | Chromiumの実行パス。既定は`/usr/bin/chromium`                             |

モデルIDを固定していません。提供元の現在のモデル一覧・利用条件を確認して選んでください。

AIの流れは「候補検索（最大24点）→ 入力の感情・背景・相反する気持ちを踏まえた1回の構造化出力 → 存在する候補ID／重複／4〜12点を検証 → 展示」です。作品の事実と編集上の解釈を分けてモデルに渡します。診断・助言・無理な励ましは指示しません。候補検索の境界は将来の意味検索に置き換えられます。

AIはOpenAIへ直接接続するAI SDKプロバイダーを使用します。追加の中継先を増やさず、一般的なOpenAIの環境変数で起動できる構成を選びました。APIキーがあっても既定は無料デモです。利用者が「AIで選ぶ」に切り替えて送信すると、その1回の選定にAPI料金が発生します。自動再試行・作品の一括AI分析はありません。35秒のタイムアウト、800文字の入力制限、2600出力トークン上限、プロセス内の同時実行上限3件を設けています。

無料デモ・同梱作品の閲覧は外部AI料金がかかりません。サーバーのホスティング・配信費用は利用するサービス次第です。AIの費用は設定モデルと入出力トークン数に依存します。

## プライバシー

入力文はサーバーのメモリで処理し、DB・履歴・localStorage・アクセス解析には保存しません。ログには入力・SDKエラー本文・AIレスポンス本文を出しません。選定完了後は入力欄の内容を破棄します。ブラウザを再読込すると展示もリセットされます。

デモの文章は同一オリジンのAPIにのみ送信します。AIモードでは入力文と必要な候補情報をOpenAIへ送信する旨を画面に表示し、Responses APIの`store:false`を指定します。これはOpenAIやホスティング事業者のすべての保持を無効化する約束ではなく、提供元のデータ利用条件が別途適用されます。

画像は通常同梱ファイルを使用します。「高精細で見る」を選ぶと公式IIIFへ接続します。高精細画像が読めなければ同梱画像に戻します。出典リンクも利用者の操作でのみ開きます。

## 作品データと権利

シカゴ美術館所蔵の実在する絵画16点を同梱しています。作品ID・所蔵番号・作者・個別の画像出典とパブリックドメイン記録を保持し、画像のSHA-256を保存元の記録と照合しました。全16点をコンタクトシートで目視し、実画像の寸法を使って比率を維持します。

この開発環境では`api.artic.edu`と`www.artic.edu`への通信が許可リストで遮断されていたため、公式APIへの直接照会・直接IIIF取得は未確認です。制限を迂回せず、すでにGitHubで公開されている作品画像と個別の権利記録をサンプルに使用しました。これは現行公式APIの直接検証と同一ではありません。

- [シカゴ美術館公式API](https://api.artic.edu/docs/)
- [公式の公開データ](https://github.com/art-institute-of-chicago/api-data)
- [サンプル画像と個別権利記録の保存元](https://github.com/haranishi/hundred-days/tree/8126fcc488c97e2d3e83926ac7975aedf94c1895/day-050-art-uncovered/data)
- 保存元が記録するWikimedia Commonsのファイルページは、`src/data/provenance.json` と作品情報UIに作品ごとに記載しています。

画像には各CommonsファイルのPublic Domain Markに従い、基本メタデータには公式APIのCC0を区別して記録します。公式APIの`description`はCC BY 4.0なので、基本データと同一視していません。今回は美術館の説明本文や保存元アプリの解説文をコピーせず、見える対象に絞った短い事実文と、独自の鑑賞上の解釈を分けています。日本語題名は便宜訳です。

詳しい取得元・ハッシュ・確認範囲は[作品資料](docs/COLLECTION.md)を参照してください。

## コレクションの拡張

閲覧時の公式APIアクセスはありません。通信可能な環境で、明示的に収集CLIを実行します。AIや有料APIは使用しません。

```bash
npm run collect -- --limit=100
```

`is_public_domain:true`、`artwork_type_title:Painting`、画像ID・作者・題名・寸法の存在を確認し、公式IIIFのJPEGを1枚ずつ保存します。取得上限は300点。既存画像は再ダウンロードせず、既存`collection.json`を自動上書きしません。取得結果は`src/data/harvest.json`です。

収集後、画像と作品ページの照合、個別権利の確認、`description`等のライセンス区別、主題・色彩・感情スコア・事実・解釈の編集を行ってから`collection.json`に追加してください。未編集の大量データをそのまま推薦に使わない判断です。現状は16点で、100〜300点への拡充は未実施です。

管理環境では`api.artic.edu`・`www.artic.edu`の通信許可が必要です。プロキシを使用するNode.js 24.5以上では`NODE_USE_ENV_PROXY=1 npm run collect -- --limit=100`を使用し、環境既定のプロキシと証明書を維持してください。

## 検証

```bash
npm run test
npm run typecheck
npm run build
npm run test:e2e
```

本番ビルドで確認する場合は `npm run build` の後、`PLAYWRIGHT_USE_PRODUCTION=1 npm run test:e2e` を実行します。テスト中は同じ `.next` を再ビルドしないでください。

E2EにはChromiumが必要です。ローカルにない場合は`npx playwright install chromium`で用意し、その実行パスを`PLAYWRIGHT_CHROMIUM_PATH`に指定してください。テストはAPIキーがない環境を想定します。

実行結果・仕様ごとの対応・検証限界は[検証記録](docs/VERIFICATION.md)に記載します。

## 残る範囲

- 実APIキーによるAIのライブ応答・実モデルの日本語選定品質・課金額は未確認です。モックによる契約検証を、実サービスの動作確認と混同しません。
- 公式API収集CLI／高精細IIIFは通信許可後に実サービスでの検証が必要です。
- 100〜300点への編集済みコレクション拡充、意味検索、永続的な分散レート制限は未実装です。同時実行上限は1プロセス内のみです。公開して有料AIを提供する場合は、提供元の予算上限と配信側の利用制限を設定してください。
- モバイルの確認範囲はChromiumの画面・タッチエミュレーションです。実機Safari／iOSの描画性能、OS固有の操作感は別途確認が必要です。
- 展示保存・共有・認証・音声・複数展示室は、体験をシンプルに保つため今回の範囲には含めていません。
