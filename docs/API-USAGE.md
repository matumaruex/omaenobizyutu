# 試験用のAPI使用量・料金

## 保存先の接続

累計、重複防止、上限判定にはUpstash Redisを使います。Vercelの「ストレージ」から無料プランの保存先を作成し、`bijutsukan` のプレビュー環境へ接続します。「立ち退き」（容量到達時の自動削除）は無効にしてください。削除・期限切れ・キャッシュにはしない記録なので、ストレージ自体を消すと累計と上限も失われます。

連携で設定される次のどちらかの組を読みます。いずれもサーバー専用で、公開用の接頭辞は付けません。

- `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`
- `KV_REST_API_URL` / `KV_REST_API_TOKEN`

保存先の認証情報をチャット・ソース・画面へ貼る必要はありません。環境変数の変更後は新しい配信が必要です。未設定・接続失敗時は有料呼び出し前に停止します。読み取り画面の障害では再選定しません。

## 確認方法と対象範囲

入口の「表示設定」で「選定結果を確認する」を有効にすると、「API使用量・料金（試験用）」を開けます。展示が未作成でも確認できます。表示は取得時点のもの。「記録を更新」は保存済み記録を読むだけで、MiMoを呼びません。自動更新や定期実行はありません。

この機能の導入後・同じ保存領域でのアプリ全体の累計です。MiMoアカウント全体の利用量ではなく、導入以前の履歴や別アプリの通信は含みません。最新100件を表示し、それ以前も累計に含めます。使用量・料金の一覧では入力文を返しません。別の選定履歴には、利用者の依頼に基づき入力文・検索候補・選定作品・短い理由・構成意図・画像の読み込み結果も保存します。内部の推論文・キー・システム指示全文は保存しません。[履歴の仕様](HISTORY.md)を参照してください。

## 実レスポンスから記録する項目

[MiMo公式のチャットAPI仕様](https://mimo.mi.com/docs/en-US/api/chat) の `usage` だけから数値を取得します。AI SDKの独自推計やトークナイザーでは補完しません。

| 表示                     | 実レスポンスの項目                           |
| ------------------------ | -------------------------------------------- |
| 入力                     | `prompt_tokens`                              |
| 出力（推論を含む）       | `completion_tokens`                          |
| 推論（出力の内数）       | `completion_tokens_details.reasoning_tokens` |
| キャッシュ（入力の内数） | `prompt_tokens_details.cached_tokens`        |

取得しなかった項目は `null` とし「未取得」と表示します。思考モードは引き続き無効ですが、推論が0かどうかもレスポンスの値をそのまま使います。選定JSONが不正で展示できなかった場合も、取得できた使用量を記録します。通信中断・タイムアウトで取得できない場合は0円と扱わず、未取得の件数を累計に併記します。

## 料金計算と変更

[MiMo公式料金表](https://mimo.mi.com/docs/en-US/pricing) の海外向け・通常の従量課金を使用します。2026年10月20日に確認したMiMo V2.6 Flashは、100万トークン当たり入力0.14米ドル、キャッシュ入力0.0028米ドル、出力0.28米ドルです。定額プラン・一括処理の単価ではありません。

`((入力 − キャッシュ) × 入力単価 + キャッシュ × キャッシュ単価 + 出力 × 出力単価) / 100万 × 円換算レート`

推論を出力に、キャッシュを入力に二重加算しません。キャッシュ数だけが未取得なら全入力を通常単価で概算し、その仮定を表示します。入力・出力のいずれかが未取得なら推定料金も未取得です。内部では円の10億分の1単位に丸め、表示時に円へ変換します。

初期の円換算は **1米ドル＝150円の仮定値** です。実勢レートは自動取得しません。単価と換算は `src/config/mimo-pricing.json` で変更できます。コードを変更しない場合は、そのファイルと同じ完全なJSONをサーバーの `MIMO_PRICING_JSON` に設定します。不正な設定では呼び出しを停止します。各記録には呼び出し時の設定を残し、後から単価を変えても過去の料金を書き換えません。

推定料金は実際の請求額ではありません。税、決済手数料、実際の決済時為替、割引、残高調整、保存先・配信費用は含みません。未取得分がある場合、累計推定料金は取得できた分だけです。実際の請求はMiMoの管理画面で確認します。

## 重複防止・上限

送信中は生成ボタンを無効にし、画面の更新前に連続した送信イベントが来ても即時ロックで止めます。依頼ごとに一意のIDを送り、サーバーではRedisの単一の原子的処理でID重複、同文の連続送信、上限を確認してから枠を予約します。異なるサーバーでも同じ判定になります。

同じIDは保存領域を保つ限り再実行しません。同じ文章を別IDで送っても60秒間は拒否します。再選定したい場合は1分待ってから改めて操作します。重複判定キーはキー付きハッシュです。入力本文は別の選定履歴へ、利用者の依頼に基づき保存します。

`MIMO_TEST_CALL_LIMIT` は初期 **50回**、設定範囲1〜1000回。同じ環境全体の累計上限で、日次リセットはありません。枠は有料送信の直前に予約します。通信障害・中断・サーバー停止・予約の応答不明も安全側に枠を消費し、実際の送信数より多く数える可能性があります。拒否された重複や上限超過は枠を増やしません。

タグ方式の1展示はタグ判定と最終選定の原則2回です。記録上の第一段階名は既存の `retrieval` を使います。各回の送信直前に別々に予約し、両方を累計に数えます。候補選びが成功して保存された場合のみ、同じ展示IDで1回だけ最終選定へ進めます。残り1枠の場合は候補選びまで実行され、最終選定は上限で停止します。過去の記録・名前空間・上限値は変更しません。

枠の確認や取得ができないときは送信しません。候補選びの保存に失敗した場合は最終選定へ進みません。最終選定後の記録更新だけが失敗した場合は、得られた展示と使用量を画面へ返し、保存失敗を表示します。自動再送は行いません。この場合の累計には未反映の可能性があります。サーバー停止時に残る予約は「応答未確認」です。

既定の保存領域はVercel環境別です。必要時のみ `MIMO_USAGE_NAMESPACE` を固定できますが、変更すると別の累計・上限になるため通常は変更しません。APIキーはMiMo側で管理し、この上限は別アプリや別環境を含むアカウント全体の請求上限にはなりません。

## 試験

通常の単体試験に加え、実Redisのバイナリがある環境で `REDIS_TEST_BIN=/path/to/redis/bin npm test` を実行すると、複数の接続からの同時重複・上限判定と、API→SDK→模擬MiMo応答→実Redis→集計の境界を検証します。実MiMoを呼ぶ試験ではありません。

## 応答時間の記録

時間設定を検証するため、呼び出しごとの `elapsedMs` を料金と同じ記録へ保存します。成功時はMiMoへの送信から応答本文の受信完了まで、失敗時は送信から失敗の確定までのミリ秒です。成功時の値に料金台帳への保存・ブラウザ通信・画像読み込みは含めません。失敗時は検証や保存処理を含む場合があります。使用量・履歴・直近の料金欄で確認でき、表示にAIは呼びません。導入前の成功履歴へ時間を補完せず、未記録なら表示を省きます。

タグ判定は最大30秒、最終8作品の選定は最大60秒。API全体の上限120秒には台帳への保存用の余裕を持たせています。これは毎回60秒待たせる設定ではなく、早く完了した応答はその時点で返します。キャンセル、自動再送なし、各回の予約・個別会計は維持します。
