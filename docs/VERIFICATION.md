# 検証記録

実施日：2026年10月17日（日本時間）。Node.js 24.19.0 / Next.js 16.4.2 / Chromium。実際に実行した結果のみを記載します。

ユーザーストーリー：感情の自由入力 → 同一オリジンの選定API → 保存された実在作品のID → 画像デコード → 白い3D展示室 → 散策・作品鑑賞 → 再入力で展示更新。

## 実行結果

| コマンド                                       | 結果                                      |
| ---------------------------------------------- | ----------------------------------------- |
| `npm run typecheck`                            | 成功                                      |
| `npm run test`                                 | 26件成功（配置11・選定／資料11・AI契約4） |
| `npm run build`                                | 成功（ページと2つのAPIルート生成）        |
| `PLAYWRIGHT_USE_PRODUCTION=1 npm run test:e2e` | 14件成功、固定した本番ビルドで実行        |

E2EはPC画面1440×1000とiPhone 13相当390×844の各7件です。タッチの移動・スワイプはChromiumの実際のタッチイベントをエミュレートし、PCのWASD・マウス固定・ESC解除・作品の3Dクリック判定も操作しています。モバイル端末そのものを使用した試験ではありません。

## 必須仕様との対応

| 項目               | 確認範囲                                                                     |
| ------------------ | ---------------------------------------------------------------------------- |
| 初回は作品なし     | 作品数0のCanvasと入力画面を確認                                              |
| 入力で展示開始     | ブラウザからAPIを呼び、4点以上の実在IDを受信して展示へ移行                   |
| 異なる感情で変化   | 喪失・期待・懐旧の選定差を単体試験、画面でも喪失→期待の更新を確認            |
| 実在する作品       | 16点の出典ID・作品ページ・個別PD記録・画像ハッシュを照合。全図を目視         |
| 画像表示           | 全16 JPEGのブラウザでのデコードと寸法を確認                                  |
| 比率・額縁         | 実画像比率を使った寸法計算、縦／横／正方形の枠内収まりを単体試験、画面も確認 |
| 可変配置           | 4〜12枚すべてのスロット数・壁内の座標・相互距離を単体試験                    |
| PC操作             | WASD移動、ドラッグ、実際の3D作品クリック、マウス固定、ESC解除を確認          |
| スマホ操作         | スティック移動、スワイプ、作品タップをエミュレーションで確認                 |
| 情報・理由         | 初期は閉じていること、情報／理由の独立した開閉を確認                         |
| 新しい感情への更新 | 展示後の再入力と異なるIDの展示への遷移を確認                                 |
| キーなしのデモ     | 本番サーバーをキーなしで起動して全画面試験を実施                             |
| APIエラー          | 入力400、異なるOrigin403、未設定AI503、模擬選定502、AIプロバイダー例外を確認 |
| ビルド             | 本番ビルド成功                                                               |

追加で、入力中・鑑賞中の移動停止と位置の保持、画像読み込み失敗からの再操作、待機中のキャンセルと入力保持を確認しました。OSの動き低減・品質設定は実装されていますが、すべての端末設定を網羅した試験はしていません。

AIの契約試験は有料通信を行わずに、候補数上限・候補ID制約・架空ID拒否・自動再試行なし・`store:false`・失敗時に入力やプロバイダー内部エラーを返さないことをモックで確認しています。AI SDKの実サービス応答を検証したものではありません。

## 修正した主な問題

- 開発サーバーが内部でURLを書き換えた際、正しいOriginを拒否していた判定をHostに基づく検証へ修正。
- 一人称カメラの初期方向を明示して、視点操作開始時の向きの飛びを解消。
- 再展示時に同じ作品も新しい画像フェードとして扱い、カメラは維持。
- デコード済み画像から直接GPUテクスチャを作り、3D表示時の二重取得を解消。
- マウス固定中のESC解除をアプリ側にも実装。
- モバイルの待機UIと下部リンクの重なりを解消し、入力UIをスクロール可能に修正。
- 停止時の現在地表示の遅れを修正。
- 4〜5点の展示でも、共鳴・別のまなざし・偶然・余韻の役割が揃うように調整。

検証中の一度のビルド更新で結果が混ざった試行は最終成功件数に含めず、サーバー終了後に作った固定本番ビルドで全14件を通し直しました。
