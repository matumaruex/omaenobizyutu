# 候補の固定化と再登場の比較試験

## 範囲

ユーザー許可: 今回の実MiMo呼び出しは合計50回まで。1展示は原則2回。
通常版 `727a8404acd8eaf3533cbcc241153481103f1e2c` と、明示的に有効化した比較版を検証する。
通常API・自分用/家族用ブランチ・認証設定・通常利用枠は変更しない。
埋め込み・追加AI評価・自動再試行は導入しない。

## 比較版

- タグ判定、候補24作品、最終8作品、30秒/60秒上限は同じ。
- 入力文だけで固定した順序を、展示リクエストのseedによる重み付き抽選へ変更。
- タグごとの順番割当、同じ作者は候補内最大2作品、否定タグと補充規則は現行のまま。
- 最近5展示（新しい順）の登場作品に0.45/0.65/0.8/0.9/0.95を掛け、重複時も最低0.2を維持。
- 抽選は指数分布の優先度 `-log(U) / weight` を使用し、再登場を禁止しない。
- 最終AIへはfittingのsituation/reasonを残し、strengthだけを省く。DBそのものは変えない。
- 適合を最優先し、同程度なら主題・表現の違いも考慮する指示を追加。
- 今回は比較用引数だけを実装。ブラウザでの直近展示保存・通常API接続はまだ実装しない。

この試験は上記変更の組合せを評価する。個別変更の因果効果を分離する試験ではない。

## データ・割付

作品DBの最新main `4cf643800a2de9a36e8b3baaf7f5b1cb47be731e` を正規化した300作品を両方式で固定使用。
`scripts/balance/catalog.json` は比較用スナップショット。通常のcatalog-seedやDBへの書き戻しはしない。

48呼び出しを最大計画とし、16呼び出しずつ3バッチで途中評価する。50回を使い切る義務はない。

- 悲しみ: 各方式6展示
- 喜びと不安の混在: 各方式2展示
- 不安の否定と無気力: 各方式2展示
- 怒り（少数タグ）: 各方式2展示

同じ入力を各方式で繰り返す。先行方式はペアごとに交代する。
タグ判定も毎回実行し、通常の2段階の時間・料金を測る。タグの変動も結果に残す。
直近展示はシナリオ・方式ごとの独立履歴とし、以前のユーザー入力や家族の履歴を使わない。
タグが同じ試行の比較も別に確認する。

## 課金・再実行防止

既存のRedis内の専用台帳 `{museum-balance-20261107}` に予約・結果・失敗・料金を永続保存。
通常アプリの台帳は調査開始時37/50回。比較試験によってその残り枠を消費しない。
通常アプリの料金画面には今回の別台帳分は含まれないため、この報告で別途合計する。

専用台帳全体で上限50。ケース/段階ごとの固定UUIDにより同じケースの再課金を防ぐ。
同文の反復は実験の目的なので、試験ケースIDを台帳の短時間重複判定に含める。
通常APIの同文60秒抑止は変更しない。
各バッチに外向きMiMo fetchの上限16も設定。失敗したケースを自動再実行しない。
保存できなければ次の有料段階へ進まない。未解決pendingがあれば次バッチを開始しない。

`scripts/balance/run.ts --paid-batch=1` のような明示指定とVercel Preview環境が必要。
普通のnpm buildやGit pushでは有料処理を実行しない。
個別PreviewのbuildCommandのみで実行し、保護された結果JSONを取得する。
キー・環境変数・SDKエラー全文・認証URLは結果に保存しない。

料金は既存の単価スナップショットによる見積り。未取得usageは不明のままとする。
実際のキャッシュ反映料金と、キャッシュなし換算を両方比較する。
応答時間は段階ごとの実測値と全体実測値を記録する。少数試行からp95やSLAは主張しない。

## 判定

- 気分への自然な接点、入力にない事情の補完、作品資料にない事実の創作、無理な励ましを人手で点検。
- 候補集合の広がり、最終展示の固有作品数、直前との重複数を方式ごとに比較。
- 候補に入る機会が増えても、最終選定が広がるとは限らない。両方を別に集計。
- 少数タグでは全関連作品が候補に入るため、抽選だけで最終展示の反復を解決できない可能性を点検。
- 「質が改善」と断定せず、具体的な選定例と限界を報告する。

## 有料実行前の検証

- 関連unit tests 47件成功（AI呼び出しはmock）。
- 型検査・production build成功。
- 明示指定のないrunnerはpaid=falseで終了し、外部APIを呼ばない。
- 通常APIは新しいsampling引数を渡さないため、現行選定を維持する。
