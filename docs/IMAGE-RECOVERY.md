# 画像読み込みの復旧（2026-11-10）

## 確認した事実

家族用Previewの22:16:36 UTCのログで、met-37907が上流HTTP 200にもかかわらずIMAGE_MISMATCHとなっていた。旧コードのこのコードは「JPEGではない」または「登録SHA-256と不一致」をまとめていたため、再圧縮・HTML応答・途中データ等のどれだったかは断定できない。今回の作業環境から美術館画像ホストへの直接アクセスは403で取得できず、実画像の再照合は未完了。

旧処理は検証前の上流レスポンスをNext Data Cacheへ24時間保存していた。異常な200レスポンスも再利用し得る構造だった。高解像度画像が失敗しても、DBにある同じ作品の通常サイズ画像は使っていなかった。ブラウザも1回の失敗で作品を除外していた。

## 変更

- 上流の生データはno-storeで取得し、JPEGとSHA-256を検証した出力だけをCDNへキャッシュする。ハッシュの自動更新・検証省略はしない。
- 通常時は高解像度を1回取得。通信失敗、タイムアウト、5xx、429、非JPEG、不一致のときのみ高解像度を1回再試行する。404や403などは同じURLを繰り返さない。
- 高解像度が使えなければ、そのDBリビジョンに登録された通常サイズURLと独立したSHA-256で同じ作品を取得する。別作品への差し替えはしない。代替URLがない作品には再試行だけを適用する。
- 1つのサーバー要求は全体45秒以内、高解像度25秒＋再試行8秒＋通常サイズ10秒。代替なしの再試行は18秒。成功時はそこで終了する。
- 通常サイズの応答はブラウザ・CDNとも60秒だけ保存し、低解像度のまま1年固定しない。高解像度は従来のブラウザキャッシュ＋CDN 24時間を使用する。
- ブラウザの画像取得・デコード失敗も1回だけ再試行。元の70秒の制限を共有し、キャンセル時にタイマーと要求を停止する。全て失敗した場合は従来の部分展示の通知を残す。
- 分類済みDBキャッシュのキーを更新し、過去のキャッシュにも代替画像情報が反映されるようにする。
- 失敗ログはIMAGE_NOT_JPEG/IMAGE_MISMATCH/IMAGE_TIMEOUTを分離。復旧時もartwork_fetch_recoveredへID、試行数、通常サイズか、失敗種別だけを記録する。
