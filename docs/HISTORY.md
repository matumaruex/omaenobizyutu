# 選定・料金の履歴

利用者の依頼に基づき、入力文と選定結果も試験用に保存します。既存のUpstash Redisと保存領域を使うため、追加の接続設定や課金プランの変更はありません。使用量の累計・上限はリセットしません。

## 画面

入口の「表示設定」→「選定・料金の履歴（試験用）」を開きます。この履歴ボタンは確認表示の設定がオフでも表示します。部屋の入力欄からは「選定結果を確認する」がオンのときに開けます。

最新から20件ずつ表示し、「以前の記録」「新しい記録」で移動します。記録を開くと、入力文、最終選定作品の名前・ID・作者・配置順・短い理由、展示全体の構成意図、使用トークン数、呼び出し時の推定料金・単価・換算設定を確認できます。保存した作品名を使うため、後からDB上の題名を直しても過去の表示は変わりません。

「候補検索から選定までの流れ」には参照DB版、候補、最終選定との対応を表示します。今回の試作は `method: ai-tags-v1` です。第一段階のMiMoには入力原文とDBに実在するタグ・その意味だけを渡し、文脈から選んだタグと否定されたタグを保存します。作品資料はこの段階では送りません。プログラムが各タグから順番に候補を取り、同じ作者は最大2点、全体で最大24点とします。一致が少なければ他の作品（タグなしを含む）で補います。同条件の順序は入力と作品IDから安定したハッシュで決め、作品ID順の偏りを避けます。「一致タグ数」は表示用で順位には使いません。

前の全作品方式 `ai-semantic-v1/v2/v3` の履歴は、当時AIに渡した全作品数と提案された候補を表示します。`v1` に候補理由があれば、そのまま表示します。さらに以前の語彙検索履歴も、当時の点数・分類・絞り込み方法をそのまま表示します。タグ方式で過去の履歴を書き換えません。

候補選びと最終選定は別の有料呼び出し・記録IDです。同じ `pipeline.exhibitionId` と段階名で関連付け、それぞれ使用量・料金・成否を残します。候補選びの記録には8作品の展示結果がなくても正常です。最終選定の記録に8作品と画像結果を保存します。

履歴・詳細・ページ移動・再読み込みは保存済みデータの読み取りだけで、MiMoを呼びません。画面を閉じる・退出する・ページを再読み込みする・別の展示を作る操作でも、過去の記録は消えません。保存先自体を削除すると消えます。

## 記録の内容と限界

入力と候補検索は送信枠の予約と同じ原子的処理で保存し、料金と同じ記録IDを使います。候補選びの結果は検証後、料金・入力・候補スナップショットと同じ原子的処理で保存し、これが成功してから最終選定の送信枠を個別に予約します。正常な最終選定結果も検証後、料金更新と同じ原子的処理で保存します。選定に失敗した場合も、取得できた入力・検索・使用量・成否は残ります。保存失敗時は既存の警告で伝え、モデルを再呼び出ししません。

画像の読み込みが終わった時点で、ブラウザから読み込めた作品IDを1回報告します。選定されても読み込めなかった作品を履歴に表示します。これは画像デコードの結果であり、全フレームで実際に描画されたことの保証ではありません。中断・通信障害などで報告を受け取れない場合は「未報告」です。報告は有料AIを呼ばず、成否や回数上限を変更しません。

選定履歴の追加前の記録は、使用量と料金だけが残っています。過去の入力・候補・選定結果は保存されていなかったため復元しません。履歴画面でもその旨を表示します。

APIキー、Redisの認証情報、AI内部の推論文、システム指示や候補資料の全文、エラーの生の応答は保存しません。履歴はURL・アプリログ・ブラウザの永続ストレージへ転記しません。

選定失敗時は料金記録の `failure` に、固定分類・問い合わせ開始からの所要時間・取得できたHTTP応答番号を保存します。条件不一致の場合は、タグ形式・作品数・重複ID・候補外ID・説明の長さなど、固定の検証項目名も記録します。認証、利用制限、MiMo側エラー、リクエスト拒否、通信、時間切れ、中断、不正な応答、展示条件不一致を区別し、使用量欄と履歴で日本語表示します。サーバーログにも記録IDとこの安全な分類・数値だけを出します。SDKの例外、入力、キー、応答本文は出しません。導入前の失敗理由は復元できません。使用量が取れなかった失敗は0円と扱わず、料金未確定と表示します。これによる自動再送・追加のAI呼び出しはありません。

## 読み取りとアクセス

Vercelの認証保護を維持した確認用アプリの、同じ環境の利用者で共有する試験履歴です。ユーザーごとの履歴分離は行いません。

- `GET /api/history?offset=0&limit=20`：料金と結び付いた選定履歴。1回の表示上限は50件。
- `GET /api/usage`：使用量・推定料金の累計。入力や選定本文は含めません。
- `POST /api/history/[id]/display`：記録に含まれる作品IDだけを画像結果として受け付けます。

応答はすべて `no-store`。現在のVercelコネクターで認証付きの確認用URLを取得すれば、Codexからも履歴を参照できます。参照時に利用者がキーや履歴の本文をチャットへ貼る必要はありません。常時監視ではなく、調査時に取得します。

保存領域は既存の `MIMO_USAGE_NAMESPACE` を使用し、記録・選定スナップショット・画像結果を分けて保存します。JSONの配列をLuaで再エンコードせず、空配列もそのまま保持します。既存の送信数・重複キー・単価スナップショット・料金集計は維持します。
